# Reproducible pipelines

## Canonical inputs and staging

Use `tools/project.py`, not direct execution under `pipelines/`. The shared helper prepares an isolated `build/film`, `build/tour`, `build/watch`, or `build/export` working directory. It copies each tracked input once, including the shared model and fonts. Later operations reuse generated scenes and frames. An input fingerprint refuses stale rebuilds when tracked inputs change. Remove the affected generated `build/<pipeline>` directory to reset it, then rerun the command. Do not edit staged scripts; edit tracked `pipelines/` inputs.

Each original sensor-scene copy was byte-identical, so all pipelines share `models/Sensor_Mechanism_Panorama.blend`. `source/film/Approved_v3.blend` is **not** an obsolete alternative: it is the distinct required baseline for `build_v4.py`, which shifts animation by 720 frames and adds the panorama. It remains an explicit build dependency. The watch scene is a distinct derived integration and is retained.

Original visual algorithms and timings are preserved. Integration changes remove machine-specific/fallback paths, add subset render options, consolidate assets, and provide shared orchestration. Existing `.blend` files contain packed Open Sans and DejaVu font data; old font-origin paths stored inside the scenes are not runtime dependencies. Font data required by Python composition is also bundled.

## Film

Default render uses the accepted final scene. `build film` reconstructs the native scene from the baseline; subsequent `render film` recreates visibility metadata and all native frames. `compose film` generates the 174-second MP4 in four segments, exports tracked label layouts, and finalizes the editable scene in staging.

The 4,176-frame film uses camera-facing BVH depth tests against evaluated opaque hardware. Soft luminous paths are clipped with RGB masks; hidden-view guides are dashed and non-luminous. Transparent window films and illustrative particles are excluded from that opaque mask. This visual treatment is not a physical optical propagation model. All metadata, visibility masks and editable typography layouts are regenerated by the render/composition steps and omitted from the distribution.

Partial renders save `preview_metadata.json`; full renders save `metadata24.json`. Partial renders never overwrite complete reference metadata. Composition of a full film requires all base frames and corresponding masks. No old sibling-directory caches are reused.

## Tour

The canonical clean sensor hardware is frozen and viewed at 480 native angles. Component-relative label trajectories use a circular global optimization with regularization, soft visibility transitions and crossing fades. Fixed corner labels are not used. Full composition requires the complete base-frame sequence; the explicit smoke subset is for checking one labeled image only.

MP4: 960×640 at 15 fps, 32 seconds. GIF: 720×480, 480 frames, 32 seconds, infinite loop; GIF delays alternate 60/70 ms. GIF validation also checks geometry-derived label metrics and decoded unique-frame counts.

## Watch

`build watch` regenerates the watch from the accepted sensor, applies the final caption and measurement-stage treatment, and verifies all 51 hardware object meshes and local transforms. A single parent gives a uniform scale of 0.285 and 180° rotation. The watch shell and local fade are illustrative; no manufacturer CAD is used. `render watch` uses the prepared native 320-frame scene.

MP4: 960×720 at 16 fps, 20 seconds. GIF: 800×600 at nominal 12 fps, 240 frames, 20 seconds, infinite loop. Because the GIF cadence differs, it samples the native sequence; the MP4 preserves all 320 native renders.

## Output handling

Film outputs: `build/film/`; tour outputs: `build/tour/build/`; watch outputs: `build/watch/`; GLB outputs: `build/export/`. To publish a revised release, review outputs, explicitly copy selected results into canonical `media/` or `models/`, update provenance and regenerate `release/manifest.json` and `release/SHA256SUMS.txt` with `python tools/release_manifest.py`. Then rerun `validate`. Updating a manifest records bytes; it does not establish scientific or visual approval.

FFmpeg encoding requires complete sequences. Cached inputs must match the same geometry, camera, materials and scripts. Smoke results are intentionally separate from accepted release media and do not demonstrate a full end-to-end rerender.

## Lossless source packing

The three Blender files were recompressed using stronger Zstandard compression to fit a single archive. Their **decoded Blender bytes are unchanged**; `release/blend-compression.json` records original, decoded and repacked SHA-256 hashes. This is storage-only compression, not geometry simplification or a model rebuild. Blender opens these files directly; end users do not need a separate Zstandard package.
